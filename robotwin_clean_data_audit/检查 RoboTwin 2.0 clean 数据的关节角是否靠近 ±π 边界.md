# 任务：检查 RoboTwin 2.0 clean 数据的关节角是否靠近 ±π 边界

## 背景

VLAct 论文（附录 F）在 RoboTwin 50 任务 × 50 条 clean 数据上做了消融：

| 设置 | Clean 成功率 |
| --- | ---: |
| 直接回归原始关节角 | 75.5 |
| 关节角 wrap 到 [-π, π] | 78.6 |
| + wrap-aware loss | 80.5 |

原理：179° 和 -179° 物理上只差 2°，但普通回归把它们算成差 358°。

**这招有没有用，完全取决于数据里的关节角是否真的会碰到 ±π 边界。** 如果所有关节都在 ±2.5 rad 以内活动，wrap 对数据没有任何改变，可以直接放弃这个方向。

本任务只做统计，不改任何训练代码。

---

## 第 0 步：先摸清数据格式，不要直接写分析脚本

数据集：`TianxingChen/RoboTwin2.0`（HuggingFace）

**不要整个下载**，里面有大量图像，体积很大。先：

1. 用 `huggingface_hub` 列出仓库文件结构，找到 Aloha-AgileX clean 数据所在目录
2. 确认数据格式（hdf5 / LeRobot parquet / 其他）
3. 只下载 2–3 个任务的数据，用 `allow_patterns` 排除图像文件
4. 打开一个 episode，打印所有字段名、shape、dtype，确认：
   - 动作字段叫什么（`action` 或其他）
   - 状态字段叫什么（`observation.state`、`joint_state` 或其他）
   - 维度布局：预期是 14 维 = 左臂 6 关节 + 左夹爪 + 右臂 6 关节 + 右夹爪，**但必须以实际数据为准**，不要按预期硬编码
   - 单位是弧度还是角度

把第 0 步的发现先写进报告，再继续。

## 第 1 步：确认 LingBot 实际用的动作表示

去 `https://github.com/Robbyant/lingbot-vla-v2` 找 RoboTwin 相关的数据处理和 config，确认：

- LingBot 在 RoboTwin 上用的是**绝对关节角**、**delta 关节角**，还是**末端执行器位姿**
- 训练前有没有做归一化，归一化方式是什么

**如果 LingBot 用的是 delta 动作或末端位姿，wrap 问题基本不存在**，第 2 步只需要跑一遍确认，报告里写清楚即可。

## 第 2 步：统计（所有 50 个任务）

确认格式后，下载全部 50 个任务的 clean 数据（仍然排除图像），对**动作和状态两个字段分别**统计。只统计关节角维度，夹爪维度排除。

对每个关节维度输出：

1. **范围**：min、max、1% / 99% 分位数
2. **靠近边界的比例**：|θ| > 0.9π 的样本占比；|θ| > 0.95π 的样本占比
3. **越界数量**：|θ| > π 的样本数（如果有，说明数据没有 wrap 过）
4. **轨迹内跳变**：每条轨迹相邻两步的 |Δθ|，统计 |Δθ| > π 的次数——这是最关键的指标，出现就说明有角度跨越边界的情况
5. **跨边界轨迹数**：有多少条轨迹的某个关节曾经同时出现 θ > 0.9π 和 θ < -0.9π

再按任务汇总：哪些任务出现了靠近边界或跳变的情况。

## 第 3 步：画图

每个关节维度一张直方图，x 轴标出 ±π 和 ±0.9π 的竖线。12 个关节拼成一张大图即可。

## 判定规则

| 统计结果 | 结论 |
| --- | --- |
| 所有关节 |θ| 都 < 0.9π，没有跳变 | wrap 无效，放弃该方向 |
| 有关节靠近 ±π，但没有轨迹内跳变、没有越界 | 收益很小，优先级降到最低 |
| 有越界值（|θ| > π） | 数据侧 wrap 有意义，但要注意 wrap 后可能在轨迹内制造跳变，需要配合 wrap-aware loss |
| 有轨迹内跳变（|Δθ| > π） | 值得做，这是 VLAct 消融里收益的来源 |

注意第三行的陷阱：如果原始数据是**连续不 wrap** 的（比如一个关节从 3.0 连续转到 3.5 rad），强行 wrap 到 [-π, π] 会在 3.14 处制造一个 2π 的跳变。对 flow matching 动作头来说，一个 action chunk 内部出现跳变比数值越界更伤。所以报告里要明确区分「越界」和「跳变」两种情况。
